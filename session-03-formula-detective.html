🖥️ How this session runs

Seven rounds. Each round shows a real business question. Say your answer out loud before anyone clicks reveal — then we run it live against the actual cafe sheet, not just this preview.

Round 1 ☕

A 14-row excerpt from the cafe file, to work the round on screen. The real formula runs live on all 10,000 rows.

Sample excerpt — practice the formula shape here, then run it for real on the full sheet
Question

How many orders were Coffee?

🎯 Your answer first

Which formula would you write, and on which column? Say it out loud.

Formula — try it on the sample first, then the real sheet
=COUNTIF(B2:B15,"Coffee")

Counts every row in the Item column that reads exactly "Coffee." Same formula you used in Session 2 — just pointed at a different value.

Reach for this when: you need a count of rows matching one exact condition.

Now run it for real: change the range to B2:B10001 in your copy of the actual cafe sheet and see what you get.

Round 2 💵

COUNTIF tells you how many rows match. This one needs a total, not a count.

Question

Total revenue from Cash payments?

🎯 Your answer first

COUNTIF won't give you a dollar total — what's the formula that sums instead of counts?

Formula — try it on the sample first, then the real sheet
=SUMIF(F2:F15,"Cash",E2:E15)

Three arguments: where to check (Payment Method), what to match ("Cash"), what to add up (Total Spent). Order matters — the sum range comes last.

Reach for this when: you need a total filtered by one condition.

Now run it for real: change every range to row 10001 in your copy of the actual cafe sheet and see what you get.

Round 3 🥤

Not a count, not a total — this question wants a typical value.

Question

Average Quantity per Smoothie order?

🎯 Your answer first

Same shape as SUMIF, but the question asks for an average — which function?

Formula — try it on the sample first, then the real sheet
=AVERAGEIF(B2:B15,"Smoothie",C2:C15)

Same three-argument shape as SUMIF — check column, match value, average column. If this were SUM instead of AVERAGE, you'd get total Smoothie units sold, not a typical order size.

Reach for this when: you need a typical value (a mean) filtered by one condition.

Now run it for real: change every range to row 10001 in your copy of the actual cafe sheet and see what you get.

Round 4 🎯

This question has two conditions, not one. SUMIF only checks one column.

Question

Total revenue from Cash payments made In-store?

🎯 Your answer first

Payment Method = Cash and Location = In-store. What changes about the formula name and its argument order?

Formula — try it on the sample first, then the real sheet
=SUMIFS(E2:E15,F2:F15,"Cash",G2:G15,"In-store")

SUMIFS flips the order — sum range comes first, then condition pairs. Add a third pair and it works with a third condition too; SUMIF caps out at one.

Reach for this when: you need a total filtered by two or more conditions at once.

Now run it for real: change every range to row 10001 in your copy of the actual cafe sheet and see what you get.

Pivot table, part 1 📊

No new formula — a different tool entirely. Learn the translation rule once, and it works for almost any "totals by category" question.

🎯 Feel the pain first

You now know how to get total revenue for one item with SUMIF. The cafe menu has 5 items — how many separate SUMIF formulas would you need to get all 5 totals? Say the number out loud.

That's the problem

One SUMIF per item, retyped five times, one for every new item added to the menu. A pivot table gets all 5 totals in one setup — no retyping, no matter how many items there are.

The rule

[aggregation] of [number], for each [category]

"per," "by," "each," "broken down by"→ that field goes in Rows
"total"→ Values, set to SUM
"how many," "count of"→ Values, set to COUNT
"average"→ Values, set to AVERAGE
Question

Total revenue for each item?

🎯 Your answer first

Circle the category word and the number+aggregation word in that question. Which field goes in Rows? Which goes in Values, and set to what?

Translation — build this on the real sheet
Rows = Item Values = SUM of Total Spent

"each item" → category → Rows. "Total revenue" → number + aggregation word → Values, set to SUM. No formula typed — Insert → Pivot table, then drag those two fields into place.

Now build it for real: Insert → Pivot table on the full cafe sheet, drag Item into Rows and Total Spent into Values. See which item actually wins.

⚠️ Trap #1

Sheets guesses the aggregation for you — numeric columns default to SUM, text columns default to COUNT. If you drag a text field into Values by accident and get a COUNT instead of a SUM, that's normal, not broken. Check the dropdown next to the field.

Pivot table, part 2 🧮

What if the question has two categories instead of one? That's what the Columns slot is for.

Question

Revenue for each item, broken down by payment method?

🎯 Your answer first

Two category words this time — "each item" and "by payment method." One goes in Rows, one goes in Columns. Which is which, and does it actually matter?

Translation — build this on the real sheet
Rows = Item Columns = Payment Method Values = SUM of Total Spent

Item stays in Rows, Payment Method moves to Columns — same fields as before, just one more slot filled. Same numbers you'd get from several separate SUMIFS formulas, laid out as a grid instead of a list.

Now build it for real: add Payment Method to Columns on the pivot you just built. Watch the single list split into a grid.

⚠️ Trap #2

Rows vs. Columns gives you the exact same numbers — it's the same data, just rotated. The only real reason to pick one over the other is readability: a field with many categories (10+) reads better as Rows (a scrollable list) than as Columns (which spreads off-screen).

Discuss

This pivot answers what would've taken five separate SUMIFS formulas — one per payment-method-and-item pair. Which would you rather build under time pressure?

Which one, when? 🧭

Seven questions, five tools. Match each to when you'd reach for it — tap to lock in your answer, then compare with the room.

One condition, one number — SUMIF / COUNTIF / AVERAGEIF. Two or more conditions — SUMIFS. Every category at once, one or two groupings — pivot table.
